## 它是什么

**按功能组织的 DSH 生态全景图**：把打了 dsh 系列话题的 GitHub 仓库抓下来，铺成一张以
`deepseek-ai/deepseek-harness` 为圆心的扇区图。

它在 README 里**自己声明**：「这不是 DSH 插件，不依赖 DSH 运行时；它是一个独立的静态前端 + Python 采集后端。」
——所以本站把它收在**资源源**里（`sourceKind: tool`），**不**收进插件分区。

## 它抓什么、按什么分类

- **采集面**（README 列举）：`dsh` · `dsh-desktop` · `dsh-plugin` · `dsh-plugin-desktop` ·
  `dsh-plugin-market` · `dsh-plugins`；
- **圆心**固定为官方仓库 `deepseek-ai/deepseek-harness`；
- **19 个功能扇区** + **61 条细枝规则**（每个扇区下 2~5 条细枝），**按功能**而不是按标签分组；
- **三类连线**：同作者（默认开）、同扇区近邻、主题共现。度数上限只裁主题边，owner 边豁免
  （否则同一作者的项目会「断线」）；
- 节点位置由**可播种 PRNG** 决定，同一 seed 逐点可复现；
- 点扇区可放大：该扇区铺满整圆、圆内按细枝重新分扇。

## 几个值得学的产品细节

写在正文里，因为它们是这个项目最有价值的部分（不是数据，是做法）：

1. **README 里的预览图由真实数据生成**（`node tools/snapshot-svg.mjs` 复用前端的布局与配色代码），
   README 里那句原话是「不会出现『README 里的图还是三个版本前』的情况」——本站的预览截图目前全是手工的；
2. **筛选只「淡化」不移除、位置不变**——图上这比隐藏更友好（本站在分区页做的是隐藏）；
3. **访问统计拿不到接口时整栏隐藏**，不留一个空壳组件。

## 与本站的关系

**互补，不是竞争**：

- 它回答「生态里有什么、彼此像不像」——**自动、立刻更新、覆盖所有打了话题的仓库**；
- 本站回答「这是什么、凭什么这么说、谁在维护」——**人工核实、逐条出处、可认领**。

两边的口径差异要说清：它的扇区划分是**机器规则推断**，不能当作事实引用；本站在词条里引用它时，
只把它当**外部来源**。反过来，**没打话题的仓库不会出现在它的图里**（启动器、整合包、规范这类
项目往往不打插件话题），那正是本站人工分区的价值所在。

## 它连的是什么关系（这一节是回答「是不是插件关系图」）

**是关系图，但连的是「关联」，不是「依赖」。** 三类边各有来源（`src/links.js` 的注释与实现）：

| 边类型 | 条数 | 依据 | 它回答的问题 |
| --- | --- | --- | --- |
| `topic` 主题共现 | 3204 | **稀有话题共享**（超级话题已按 `hubThreshold` 排除） | 「这两条像不像」 |
| `owner` 同作者 | 764 | owner 相同（`ownerStarEdges` 55 条为星标归并） | 「这是谁家的」 |
| `neighbor` 同扇区近邻 | 前端现算 | **布局距离**（源码原话：「位置相近 ⇒ 功能相近」） | 纯视觉，不是语义 |

每条边还带一个 **`via` 字段说明理由**，例如
`{source: "imsai-sh/awesome-deepseek-harness-plugins", target: "imsai-sh/dsh-1024store", type: "topic", weight: 7, via: ["plugin-directory","registry","catalog","plugin-hub"]}`
——这是它设计上最值得学的一处：**边是可解释的**。

**它里面没有的东西**（也就是这类图最容易被误以为有的东西）：**没有任何一条「A 依赖 B / A 是 B 的前置 / A 与 B 不兼容 / A 替代 B」**。
节点里没有依赖字段，采集器也不读任何清单文件（见上表实测）。所以它是
**「生态相似度 + 归属」网络图**，不是模组依赖图那样的**有向语义关系图**。


## 未核实 / 未声明

- **实体浏览器里的最终渲染**：无头浏览器里页面能加载并显示「正在载入抽样数据…／运行正常 初始化…缩放 1.00」，
  但我**没有拿到 canvas 的最终绘制结果**，所以「图很漂亮」这句我不替它背书——请自己在浏览器里看。
- **README 预览快照坏了**：上面那条 cx/cy 全为 700 是我的实测结果。可能是快照生成器的问题，
  也可能是我取到的那一版数据本身没带上布局；**原因未核实**，不要据此说作者写错了。
- **它到底收录了多少仓库**：线上站点停在载入状态，无头浏览器里没拿到数字；
  **但仓库里就有数据集本体**（`data/mesh.json` 3.1MB，2625 个节点、3968 条边，`hourly-crawl` 快照）
  与一份**字段级契约**（`docs/data-contract.md`，含 `meta` / `tags` / `hubs` / `clusters` / `nodes` / `edges`）。
  所以「无从对接」这句是我先前写错了：**数据是开放的，只是没挂在线上站点上**
  （线上 `/data/repos.json` 仍返回 403）。本站**暂时没有**为它写 `adapter`——因为它的边是相似度，
  不是我们要的那些语义关系（见上一节）。
- **扇区与细枝规则是否准确**：61 条规则的具体内容未逐条核实；机器分类必然有误判，引用需谨慎。
- **访问统计 API**：README 说「同端口最小 API：访问数 / 同时在线，拿不到接口时整栏隐藏」，
  接口路径与隐私口径未核实。
- **许可只核到仓库根**：MIT（GitHub API 报的 SPDX）——前端与后端是否有例外条款未逐文件核对。
