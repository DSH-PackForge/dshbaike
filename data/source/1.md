## 它是什么

DSH 生态里的插件目录站。你按分类、Star、下载量找插件，它给你一份带安装命令的清单；本站刻意**不做插件全量收录**（理由见 [[tutorial/1]] 里提到的生态分工与本站的收录门槛），插件世界的地图就交给它。

它的两个特点值得记：

- **中英双语**：`/zh/` 与 `/` 各一套，连 `catalog.json` 里 `tag` 字段的中文名都跟着语言走（中文站里 `cat: "market"` 对应 `tag: "插件市场与管理"`，英文站对应 `"Plugin Markets & Managers"`）。
- **条目自带安装命令**：每个条目的 `cmd` 就是一条可直接执行的 `dsh plugin --profile web add …`。这类命令背后的机制见 [[tutorial/3]]。

## 机器可读入口：`catalog.json`

```bash
curl https://awesome-dsh-plugin.com/zh/catalog.json
```

顶层是一个对象，除了 `items` 数组，还有一组界面文案键（`install` / `market` / `cli` / `copy` / `dlTitle` 等）——**别把它当成 schema 声明**，真正的数据在 `items` 里。实测（快照 `2026-10-01`）`items` 恰为 **4400 条**，中英两份都是这个数。

每个条目 13 个字段，全部字段与本站的用法见本页 front-matter 的 `adapter.fields`。其中三处最容易读错：

| 字段 | 读法 |
| --- | --- |
| `dl` | **近 30 天**下载量（站内文案 `dlTitle` 写的是「下载量（近 30 天）」），不是累计值 |
| `npm` | 是 0/1 标记「是否以 npm 分发」，不是包名——包名在 `name` 里 |
| `href` | 形如 `/zh/p/<owner>/<plugin>/`；`name` 里出现 `#` 的（monorepo 子包）会被展平成一个 slug，例如 `/zh/p/dsh-web--packages-dsh-task-board/` |

`stars` 与 `dl` 都是**它自己的快照**。本站引用这两个数字时一律标明「引用自 awesome」并带快照日期，不自己另建统计。

## 分类：24 还是 23

这里有一处口径冲突，照实记下来：

- **首页自述「4400 个插件 / 24 个分类」**，`data/sources.yml` 也是按「24」登记的；
- 但本轮把 `catalog.json` 的 `cat` 键去重数了一遍，**中英两份都是 23 个**。

两种可能（本轮都未核实）：首页的 24 是把「全部」之类的筛选项也算作一类；或者分类在某一侧多出过一个已撤销的键。**本站现有词条与分区一律按「本站自己的 taxonomy」分类，不搬运它的 `cat`**——插件分区页展示它的时候按它的显示名（`tag`）走。

## 与我们怎么互补

| 我们做什么 | 它做什么 |
| --- | --- |
| 只给「被教程引用 / 被整合包使用 / 有人认领」的插件建词条 | 全量收录，4400 条一网打尽 |
| 写定位、关系、兼容性、坑（外部源结构上给不出的部分） | 分类浏览、Star / 下载量排序、一键安装命令 |
| 中文长文解释机制（见 [[tutorial/1]]、[[tutorial/3]]） | 条目级描述与详情页 |

所以插件分区页顶部会显式给你它这个入口；工具链分区也把它列为「别人家的工具」（点进去看全貌）。

## 一个实测到的空白

**本站收录的四个市场精选插件，在它的 4400 条里一条都没有。** 实测按 `dsh-loader`、`dsh-pack-plugin`、`dsh-packforge-app`、`DSH-PackForge` 检索，命中数都是 0；反过来看，`dsh-loader` 这类前置/兼容层在它的目录里也确实不是主流条目（按名字含 `loader` 的只有 4 条，且与本条无关）。这条空白的直接后果是：**这四个词条的热度数字没有外部源可引用**，所以它们的 `providedBy.awesome` 只能写「不在收录范围内」，而不是编一个数字。

## 怎么用它 / 怎么投稿

- **找插件**：默认从 `/zh/` 进；按分类与热度筛选，复制条目的 `cmd` 直接装。装之前请读一遍 [[tutorial/3]] 的构建授权那一段——GitHub 来源的包不是装上就完事。
- **投稿**：据本站现有登记口径，投稿走 PR 并给仓库打 `dsh-plugin` 话题。**本轮未核实到一手出处**（站点没有可访问的投稿页，`/zh/about/`、`/zh/submit/`、`/zh/contribute/` 都是 404；首页是脚本渲染，抓不到出站链接）。要投稿请先自行确认它当前的收录流程。

## 未核实 / 未声明

- **许可**：未声明——`catalog.json` 里没有许可字段，站点上也没有可抓到的许可声明；**我们不能假定它是某个开源协议**，所以本站只引用它的数字与链接，不复制它的条目正文。
- **分类数 24 vs 23**：见上文，未核实。
- **投稿流程（PR / `dsh-plugin` 话题）**：登记口径如此，一手出处未核实。

- **详情页 URL 总量**：本站 docs 口径是「约 8800 个 URL」（每个条目中英各一页）；本轮只逐条核实了 `href` 的形状与拼法，**没有**逐条探测 8800 个 URL。
