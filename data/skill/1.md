## 它到底做什么

一句话：**把「本机的一个整合包」变成「市场采集器能扫到的一行索引」**。它不管包怎么打（那是 [[tool/1]] 的活），只管发布侧的硬约束与顺序——因为市场是**按 GitHub 上的事实扫描**的，任何一处不齐，结果都不是报错，而是「什么都不会发生」。

这也决定了它的形状：不是一段代码，而是一份**可执行清单**，加一张坑表。

## 六个步骤，和三处「缺一不可」

| 步骤 | 动作 | 校验点 |
| --- | --- | --- |
| 1 | 收集 `<owner>` / `<name>` / `<version>` / `<tag>` | `name` 与 `version` 跟根 `manifest.json` 逐字一致，`tag = v<version>` |
| 2 | 出产物：路径 A `dspack pack --repo`，路径 B 手工摆 `manifest.json` 加 `overrides/` | `release/` 里 `.dspack` 与 `.dspack.sha256` 两个文件都在 |
| 3 | `gh repo create <owner>/<name> --public --source . --push`，再 `gh repo edit … --add-topic dsh-pack` | public、有 `dsh-pack` 话题、未 archived |
| 4 | `gh release create <tag> …dspack …dspack.sha256 --title …` | 非 draft、非 prerelease，资产恰好两个 |
| 5 | 逐项过六条校验清单 | 侧车必须是 64 位小写 hex |
| 6 | 告知「收录是异步的」 | 等一轮采集后再查市场索引 |

**三件硬事**（缺一即静默失败）：public 仓库、`dsh-pack` 话题、默认分支根的 `manifest.json`。**一条限制**：同一 Release 只放一个打包资产——采集器按 `.dspack > .tgz > .zip` 取第一个，混放会装到旧包。

## 五个坑，都是「不报错」的那种

- 仓库私有 / 漏打话题 / 已 archived → 市场扫不到，任何界面都不会提示。
- Release 是 draft 或 prerelease → 索引里有条目，下载却取不到（`releases/latest` 拿不到）。
- 同一 Release 混放多个资产 → 装到旧包。
- 侧车写了大写 hex 或夹带文件名 → sha256 校验失败。
- tag 与 `manifest.version` 不一致 → 索引键错位。

这张表和上游 README 的区别在于：**它把「失败时的现象」写出来了**，而现象全是沉默。

## 本机实测：它是插件形态，不在技能目录里

本站要提醒的一点：`publish-to-github` 在本机**并不住在 `$DSH_HOME/skills` 下**。按技能发现根契约（见 [[concept/3]] 里 `skills/` 那一行与 `@deepseek-ai/dsh-skill-filesystem` 的 rank 表），用户级根是 `<dshHome>/skills`，但实测那份目录的 20 个条目里没有它；它由 [[plugin/2]] `@dsh-packforge/dsh-pack-plugin` 以**插件技能提供方**注册（技能目录里 provider 记为 `dspack`），包内路径是 `lib/publish-to-github/SKILL.md`。

仓库侧另有一份同名文件 `skills/publish-to-github/SKILL.md`。两份**不是同一份**（5344 / 5476 字节，sha256 不同）。要改这条技能，先确认改的是哪一份——这是本站目前能给出的最实用的一句提醒。
