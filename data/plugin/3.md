## 它解决什么问题

一个 `.dspack` 包在被别人装走之前，得先生成、先校验、先讲清楚里面有什么。**dsh-packforge-app 就是这套「包的生产线」**：图形客户端负责看与点，`dspack` 命令行负责塞进脚本和 CI，两者背后是同一份打包引擎。市场给它的分类是「工具」，徽标是「整合包必备」，登录条目见 [[source/2]]；它同时占着启动器分区的一个 canonical ID（`dsh-packforge-app`）。

它与 [[plugin/2]] 的分工是**同一件业务、两个宿主**：它在 DSH 之外运行，dsh-pack-plugin 在 DSH 界面里运行；README 也把这条写成原则——「一个引擎，多个宿主：pack/install 的业务规则只存在于 core，GUI 与 CLI 绝不复刻」。

## monorepo 里有什么（实测 6 个 workspace）

本地 checkout 的 `packages/` 下每个目录都有自己的 `package.json`：

| 包名 | 目录 | 是什么 |
| --- | --- | --- |
| `@dsh-packforge/core` | `packages/core` | 主机无关引擎：容器、manifest 校验、坐标转换、安全过滤 |
| `@dsh-packforge/host-node` | `packages/host-node` | Node 适配器（CLI / Electron / server） |
| `@dsh-packforge/host-dsh-plugin` | `packages/host-dsh-plugin` | DSH 客户端插件适配器 |
| `@dsh-packforge/cli` | `packages/cli` | `dspack` 命令（`bin` 指向 `./bin/dspack.js`） |
| `@dsh-packforge/gui` | `packages/gui` | Electron 桌面端（`main` 是 `electron/main.mjs`，`private: true`） |
| `@dsh-packforge/plugin` | `packages/plugin` | DSH 客户端插件半端 |

真正带 DSH 声明的是最后那个包：它的 `package.json` 同时有 `dsh.bundle.patch`（指向 `./cordis.patch.yml`）与 `dsh.client`（`platform: web` + 四个 inject）。**这正好是一个「bundle 声明 + patch 层」的现成样本**，[[tutorial/2]] 就是拿它当例子的。

## 内部的一条纪律：I/O 全走 Host 接口

README 与 toolchain 分区都强调同一条：`core` 不 import `node:fs` / `node:crypto`，I/O 一律经 `Host` 接口注入，所以引擎能脱离 DSH、脱离 Electron 单独测试。代价是多一层适配器（`host-node` / `host-dsh-plugin`），收益是 GUI、CLI、插件三种宿主跑的是同一套规则——**包成分表的解析器就在 `core` 里**，这是本站在整合包词条里展示「层栈 → 钉死版本 → patch 改了什么」的数据来源。

## 谁在用它

- **启动器认领表**：`launchers.json` 里第 3 条就是它，`support` 写「官方工具链」，`desc` 是「DSH PackForge 图形客户端与 dspack 命令行：导出、浏览、安装整合包」。
- **本站词条**：`data/zones/toolchain.yml` 与 `data/zones/launchers.yml` 都把它登记为对应 `plugin/3` 的条目；`data/zones/toolchain.yml` 另有一条「dspack CLI」也指向同一个仓库。
- **被教程引用**：[[tutorial/2]]。

## 未核实 / 未声明

- **它到底算不算「插件」**：仓库根 `package.json` 是 `private: true` 的 workspace 根，**没有 `dsh` 字段**；市场那条 `dsh plugin add github:DSH-PackForge/dsh-packforge-app` 是按仓库坐标写的，本轮**未实测执行**，也不清楚它最终会挂上仓库里哪个包。所以本词条的 `npm` 留空、`role` 按市场分区口径写 `bundle`，都是「照实登记上游说法」，不是本轮验证过的结论。
- **`dspack` 的命令与参数**：本轮只核实到 `bin` 名是 `dspack`，**没有**核实 `dspack` 的子命令、参数与退出码；分区页里「导出 / 浏览 / 安装」那句来自仓库与市场的自述。
- **`compat.dsh`**：未核实——仓库不给 DSH 版本区间。
- **star / 下载量 / 是否归档**：未核实。它不在 awesome 的 4400 条里；市场 `stats.json` 统计的是整合包下载量，不含工具。
- **本地规范副本**：写这一条时（2026-10-01）本地 checkout 的 `specs/` 下只看到 `workspace-config/v1.md`；**2026-10-02 复核时已变成 11 份**（manifest v1–v5、pack-structure v1–v3、index/index.md、publishing/v1.md、launcher-registry.md、workspace-config/v1.md），`spec/1` 就是读到 manifest v5 原文才写的。所以「只按公开路径引用」这句话对本文其余部分仍然成立，但**本地副本不存在**这个判断已过时。
