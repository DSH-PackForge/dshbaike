## 一句话

一个「多版本 + 多实例」的 DSH 桌面启动器：**版本**是从 npm 装下来的 `@deepseek-ai/dsh`，
**实例**是同一版本下各自独立的运行环境（名字 / profile / `DSH_HOME` 都能分别设）。
技术栈是 Tauri 2 + Vue 3（TypeScript + Sass + vue-router + vue-i18n + Arco Design Vue）。

## 它解决什么问题

DSH 装起来不难，难的是**同时用几个版本**：稳定版要长期挂着，预览版想试试新东西，
再给某个项目单独留一套环境——手工做就要来回改 `DSH_HOME` 与 profile，
一不小心就把几套环境搅在一起。它把这三层（版本 / 实例 / profile）拆成界面上的对象来管。

## 怎么用（来自 README）

- **多版本安装**：查 npm registry，把多个 `@deepseek-ai/dsh` 版本装进互不干扰的目录；
- **多实例**：一个版本下可以建多个实例，每个实例有自己的名字与 profile；
- **三种 `DSH_HOME` 模式**（这一条是它比较特别的地方）：
  ① 复用/共享一个已有的 `DSH_HOME`；② 直接接管用户默认的 `~/.dsh`；
  ③ 每个实例一个独立 `DSH_HOME`（在应用数据目录下自动创建并登记）；
- **装插件是向导式的**：选插件 → 选版本通道与版本 → 选实例 → 选 profile → 建；
  插件来源是 [DSH 插件市场](https://dsh-plug.in/)；
- **三种版本通道**，界面上用彩色字母区分（`stable` 通道取 releases / npm `latest`）；
- **按 profile 管插件**：实例设置里有 Plugins 页签，可以按 profile 过滤看装了哪些；
- **WSL2 实例（实验性）**：可以在 WSL2 发行版里建 DSH 实例，插件与整合包依赖的
  `pnpm` 在发行版内跑（拉的是 Linux 平台二进制）。已知限制：WSL 的 `DSH_HOME` 暂不支持存储重定向。

## 两件要留意的事

1. **它会自动放行依赖的构建脚本**：README 写明 `onlyBuiltDependencies: ['*']`
   ——也就是装依赖时不逐个人工确认构建脚本。方便，但代价是你少了一道把关（本站的
   「⚠ 构建脚本」徽章讲的就是这类行为）。
2. **从源码构建的前提**：README 列的是 Node ≥ 20、pnpm、stable Rust（MSVC 工具链）、WebView2
   ——这些出现在构建/开发章节；**发布版运行时是否也需要这些，本轮未逐条核实**。

## 身份与格式支持

- **canonical ID：未认领**（2026-10-02 查规范仓库的 launcher-registry 与市场 `launchers.json`，
  都没有它）。含义：整合包**暂时没办法**在 manifest 的 `launchers` 字段里声明它，
  只能靠 README 让人手装。认领方式见启动器分区的 howto。
- **支持 `.dspack`**：★编辑确认（2026-10-02）。README 这一份里**没有出现 `.dspack` 字样**，
  只在 WSL 那段提到「modpack 依赖安装」——所以这条事实的依据是站方而不是仓库文档。
