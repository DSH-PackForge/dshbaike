## 一句话

**HMCL 内核**的 DSH 启动器与版本管理器：下载安装任意已发布的 `dsh`、
为每个实例保留独立的运行环境与 `DSH_HOME`、管理插件，并且从 v0.2.0 起能把整合包**导出**成
PackForge 协议格式。

## 它解决什么问题

DSH 通过 npm 发布、以 `dsh web` 启动——对熟悉 MC 启动器的人来说，这套流程应该由启动器代劳：
挑版本、装下来、隔开环境、想换版本不用重装。HDSL 就是把这一套搬过来的那一支
（它的自我描述是「最原汁原味的体验」）。

## 怎么用（来自 README）

- **下载并安装任意已发布的 `dsh` 版本**，为每个实例保留独立的运行环境与 `DSH_HOME`；
- **版本覆盖范围**（README 的措辞）：从最古老的 `v0.0.1-rc1` 到最新的 `v0.1.7-rc.1`，
  靠的是「高度定制化启动策略」；
- **整合包**：v0.2.0 起支持 **PackForge 协议整合包导出**，可以在
  [PackMarket](https://dsh-packforge.github.io/dsh-pack-market/) 一侧配合使用；
- **插件**：v0.2.0 起支持从 NPM 源安装指定插件，也支持从本地安装；
- **分发**：Linux 侧打包成 `.deb` 与自解压脚本。

## 环境要求（README 的表格）

| 项 | 要求 |
| --- | --- |
| 操作系统 | **Linux / macOS**（x86_64 / aarch64） |
| 运行时 | Java 21（构建与运行） |
| DSH 侧 | Node.js `^22.19.0 \|\| >=24.0.0`，以及用于插件管理的 `pnpm` |

## 身份与格式支持

- **canonical ID：`hdsl`** ✅ 已认领（规范仓库 launcher-registry + 市场 `launchers.json`）。
  含义：整合包**可以在** manifest 的 `launchers` 字段里声明支持它。
  注册表还记了它「可自报」版本，但自报格式未核实。
- **支持 `.dspack`**：✅ 有 README 依据——v0.2.0 说明里明确写了 PackForge 协议整合包导出。
  它另有自有的 `.hdslp` 格式（启动器分区卡片记的）。
- **与 `dshl` 的关系**：名字只差一个字母，**内核与实现完全无关**（这个是 HMCL 系，那个是 PCL 系）。
  整合包 manifest 里写 `hdsl` 与写 `dshl` 指的是两个东西。

## 未核实 / 未声明

- **`.hdslp` 与 PackForge 格式的关系**（是否能互转）：README 未说明，本轮未核实；
