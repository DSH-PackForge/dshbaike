## 一句话

面向 Windows x64 的图形化启动器**与生态管理器**（.NET 8 WPF）：管多个 DSh 版本、
运行实例、Plugin、Skill、Provider 和对话文件；能在**没有 Node.js 或 DSh 的机器**上先跑起来。

## 它解决什么问题

其他启动器大多从「把 DSH 装上并起得来」出发；它的出发点更接近「把整台机器上的 DSH 生态管起来」：
版本、实例、对话、插件、技能、Provider 都在一个界面里，而且**导入导出整合包时做校验与脱敏**。

## 多版本与多实例（README）

- 新建与复制出来的版本使用独立的 `DSH_HOME` 与 `DSH_AGENTS_HOME`；
  也可以直接**关联其他桌面端已有的** `DSH_HOME`（不强迫你迁移）；
- 支持复制现有版本、新建干净版本、删除版本、改版本名；
- 同一个 DSh 运行目录可供多个隔离版本使用，**并可同时启动多个实例**；
- 每个版本的「打开窗口」可以绑到 DSH Desktop，或本机的 EXE / BAT / CMD / PowerShell 脚本 / LNK 快捷方式。

## 整合包与市场（README）

- 支持导入导出 **Launcher `.dshpack`** 与 **DSH-PackForge ModPack v2 `.tgz`**，
  并且**两者可双向转换**；目录式 Skill 的常见文本脚本会随包保留并**脱敏**
  （密钥、dotenv 与会话不进包）；
- 从「下载 → 整合包」里搜索
  [DSH-PackForge 社区市场](https://dsh-packforge.github.io/dsh-pack-market/) 的整合包，
  下载内容按**大小与 SHA-256 校验**；
- 可从市场或本地导入 **`.dspack` Profile 包**（容器 v2/v3，manifest v4；v3 也接受 manifest v5），
  映射到隔离版本的 `profiles/web`，直接依赖按清单**固定版本**或复用。

## 身份与格式支持

- **canonical ID：未认领**（2026-10-02 查规范仓库 launcher-registry 与市场 `launchers.json`，
  都没有它）——整合包**暂时声明不了**它。
- **支持 `.dspack`**：✅ 有 README 依据——它明确写了 `.dspack` Profile 包的容器与 manifest 版本，
  以及 ModPack v2 `.tgz` 与 `.dshpack` 的双向转换。这是这一区里对整合包格式讲得最细的一份文档。
