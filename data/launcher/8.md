## 一句话

它不是「一个启动器」，而是**一对东西**：装进 DSH 的是一个 **Web 插件**（宿主半 + 浏览器半），
桌面那一侧是一个 **Tauri 桌面应用**；仓库同时附带桌面应用的完整源码与 Release 自动构建流程。
装好后在「**设置 → 桌面启动**」里就能一键唤起它。

## 它是什么、不是什么

- **是**：DSH 界面里的桌面端开关——启动 / 退出、运行状态、桌面快捷方式、关闭确认；
- **不是**：它**不装 DSH 版本、不管 profile、也不导整合包**（README 全文没有版本清单或 `.dspack`）。
  也就是说，它和这一区其它启动器（选版本、隔离环境、装包）解决的不是同一个问题——
  它是「把桌面包挂进插件生态」的那条路。

## 功能（README）

- **桌面端启动开关**：一键启动 / 退出桌面应用（点击即反馈，秒级状态同步）；
- **快捷方式联动**：开启时自动创建桌面快捷方式、关闭时自动删除；运行中可手动补建；
- **关闭确认弹窗**：关闭前弹窗确认（含「快捷方式将被删除」的提示）；
- **状态可视**：🟢 运行中 / ⚪ 已停止 / 🟡 状态未知，出错时显示诊断信息；
- **深色模式适配**：全部颜色走 DSH 主题令牌，深浅色自动适配；
- **设置导航图标**：替换默认齿轮图标（矢量绘制，任意缩放锐利）。

## 工作原理（README 摘要）

- Web 插件的**宿主半**通过回环路由 `/api/dsh-tauri-launcher/*` 与浏览器半通信；
- 桌面应用每秒写一次 `.dsh-heartbeat` 时间戳，插件以此**探测运行状态**（不靠猜进程）；
- 插件按优先级自动探测桌面应用的候选目录（npm 包内预编译 exe、本地 `build.ps1` 产物）。

## 平台支持（README 的表格）

| 平台 | 状态 |
| --- | --- |
| **Windows** | ✅ 已支持（含桌面快捷方式 `.lnk`） |
| Linux | 🚧 规划中 |
| macOS | 🚧 规划中 |

Web 插件本体（host / client JS）跨平台；目前 Windows 专属的实现集中在**桌面快捷方式创建**与
**回环进程控制**上。

## 怎么装（README）

```text
# 1) npm（发布后）
# 2) GitHub（git 安装）
dsh plugin --profile <profile> add github:cilis/dsh-tauri-launcher   # 具体命令以 README 为准
```

README 特别注明：Git 安装这条路 **纯 JS 零构建，不需要 `allowBuilds` 授权**——
在这一区里比较少见（别的启动器往往要跑构建脚本）。配置项都在插件行里给，
没有硬编码的可调参数；原 `shortcutName` 配置项已于 2026-09 移除。
