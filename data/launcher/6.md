## 一句话

**轻量启动器**：选一个版本，起 DSH 的**官方原版 Web 页面**。
它明确不重做界面（「不修改也不重做 DSH 的网页界面」），把力气花在版本、插件与整合包的管理上。

## 它解决什么问题

官方形态是「装 Node、`dsh web`、开浏览器」。DSH-X 把这几步收成一个安装包，
并且**自带便携的 Node / npm / pnpm**（含 npmmirror 镜像源）——所以**不依赖系统里装了什么**。
对「我只想快点用上，不想动开发环境」的人，这是最省事的一支。

## 功能面（README）

- **选版本即用**：启动 / 停止 / 重启 / 更新 / 卸载；
- **多操作系统**：Windows 与 macOS 都有原生安装包（macOS 分 Apple Silicon 与 Intel 两份），
  自更新、开机自启、选目录都用各系统自己的方式；
- **插件页**：列出已装插件一键开关、可检查并更新（单个 / 全部），profile 也在这里切；
- **兼容模式**：启动失败时按报错**自动禁用出问题的插件**（可一键恢复）；启动后自检页面引用的
  客户端插件包，管理页给出结论（并区分实例问题与旧标签页）；
- **常驻后台**：关掉网页不退出（Windows 托盘 / macOS 菜单栏图标），界面走系统浏览器；
- **网络代理**：跟随系统（默认）/ 手动填地址 / 不走代理，代理连不上自动退回直连；
  版本列表、GitHub、市场与插件安装都按它走。

## 整合包（这一区里讲得最细的一份文档）

- **一张卡就是一份 profile**：装完整合包，产物正是它；手动拼出来的 profile 也在列表里，
  装过包的那张标着来源；
- **从哪装**：本地 `.dspack` 文件、直链、GitHub 的 `owner/repo`（自动取最新 Release 里的包），
  或直接在页面上从**内置社区市场**挑；
- **装之前先说清**：层栈、依赖、要写的文件、会覆盖什么、包里**哪些内容不会装**
  （凭据、`.npmrc`、整机设置这些一律不落盘），确认了才动手；
- **自己也能发一个**：把当前 profile 导出成 `.dspack`
  （钉版依赖 + 补丁层 + 配置文件，不含 `node_modules` 与凭据）；
- 仓库自带一份 `packs/dsh-x-recommended`（它挑的开箱插件组合）。

> 这一条是本站目前**唯一**在 README 里把 `.dspack` 的导入来源、导出内容与「不落盘清单」
> 全写出来的启动器——所以「支持 `.dspack`」这条标签在这里是**仓库文档依据**，不是站方口径。
