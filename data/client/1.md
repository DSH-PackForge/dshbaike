## 一句话

官方 Web UI 就是**浏览器里的那个完整界面**：在装了 DSH 的机器上跑一条 `dsh web`，它起 `web` profile 并把界面挂到本地 Web 服务器上。它不是一个可以单独安装的「客户端软件」，而是 `web` 这个 profile 里的一层 bundle。

## 怎么起来

本机实现（`@deepseek-ai/dsh` 的 `lib/bin.js`，实测 `0.1.0-rc.6`）把这件事写得很直白：

| 你敲的 | 实际发生 | 依据 |
| --- | --- | --- |
| `dsh web` | 起 `web` profile，等价于 `dsh --profile web`；`web` 是**硬编码别名**，不是普通子命令 | `lib/bin.js` 帮助文本「`web` is a hardcoded alias for `--profile web`」 |
| `dsh --profile <name>` | 起任意 profile；**不给 `--profile` 直接报错** | 同上，`--profile <name> is required` |
| `dsh web --help` | 界面的帮助，不是 CLI 的帮助 | 同上，「`dsh --profile web -h` prints the web app's help, not this one's」 |
| `dsh web --dump-config` | 打印组合后的树（含用户层） | 同上，`web` 子命令自带 `--dump-config` / `--dump-default-config` |

两件事值得记牢：

1. **「换界面」和「换 profile」在官方形态下是同一件事。** 因为 `web` 只是个 profile 名，你往 `web` profile 里装的插件会影响这个界面；反过来，插件装到别的 profile 就**不会**出现在这里。这是「我装了插件但界面没变」的头号原因，机制见 [[concept/2]]。
2. **`--profile` 是必填的。** 所以任何省略 profile 的安装或启动写法都值得怀疑——比如市场条目里给 `dsh plugin add` 却没带 `--profile` 的那种（见 [[plugin/3]] 的「未核实」一节）。

## 它其实是哪一层

照 [[concept/2]] 的 profile 契约，一个 profile 目录里 `package.json` 的 `dsh.profile.bundles` 是有序层栈。本机 `web` profile 的实测值（`$DSH_HOME/profiles/web/package.json`，2026-10-02）是：

```json
"bundles": [
  "@deepseek-ai/dsh-base",
  "@deepseek-ai/dsh-web-app",
  "@deepseek-harness-tui/dsh-tui",
  "dshmarket"
]
```

**界面来自 `@deepseek-ai/dsh-web-app`**；`@deepseek-ai/dsh-base` 是每个形态都要的基座。后两项是这台机器上的第三方/实验层（TUI 桥与插件市场），**不是官方 Web UI 的组成部分**——它们说明同一台机器上的「官方 Web UI」可以被 profile 层叠成很不一样的样子，所以拿别人的截图对不上自己的界面是正常的。同目录下 `cordis.yml` 是空数组 `[]`，只是给 Loader 当 `baseUrl` 锚点的真实文件（见 [[concept/1]]）。

## 怎么判断「我看到的界面是不是官方的」

看三处：启动命令是不是 `dsh web` / `dsh --profile web`（启动器自有入口见 [[launcher/1]]）、`dsh.profile.bundles` 里有没有多出第三方包、以及配色与文案是不是出厂值（后两者见 [[theme/1]] 与 [[asset/1]]）。**这只是排查线索，不是官方声明**——bundles 列表可以随手改。

## 未核实 / 未声明

- **入口图的下发方式**：分区条目写着「真实入口图由 `window.__DSH_BOOT__` 下发」。本轮在本机可读的 `@deepseek-ai/*` 包里**按 `__DSH_BOOT__` 检索无命中**，所以这条**未核实**——本站照抄分区条目的措辞，不替它背书。
- **版本区间**：官方源没有给出「这个界面支持哪些 DSH 版本」的声明，`compat.dsh` 因此只有一条「未核实」。
- **平台**：分区条目只写 `platforms: [browser]`。「哪些浏览器」未核实。
- **许可证**：实现侧包一律声明 MIT（实测 2026-10-02）；**DSH 本体仓库根的 LICENSE 本轮未读取**，未核实。
- **端口、托管方式、是否自动开浏览器**：`dsh web` 的默认监听地址与行为本轮未实测。
- **`repo`**：取自分区条目的 `links.github`，是**厂商仓库**；本机 `@deepseek-ai/dsh` 的 `repository.directory` 是 `apps/cli`，界面在 `packages/client/*`——同一仓库、不同目录。
