# 08 · 视觉系统（现代 Wiki / 索引式）

> 状态：**设计稿（待评审）**。本文定站点的视觉语言与组件规范。
>
> **不沿用 `dsh-pack-market` 的「纸墨朱砂」。** 市场是**宣传页**取向（hero 插画、大留白、卡片阴影、装饰性 SVG 动效），百科是**索引与工具**取向。两套视觉混用会让读者分不清「这是介绍页还是查资料的地方」。
>
> 参照的是 MC百科的**信息结构与密度**（已核实：条目页分块 + 信息表 + tab 计数 + 表格化的资料列表 + 数据来源标注），而**不是它的配色与样式**——其具体色值未核实（抓取只取到文本，样式表未核对）。因此本文的配色与字体**是自定的**，并明确标注取舍理由。

## 1. 七条设计原则

| # | 原则 | 具体含义 |
| --- | --- | --- |
| 1 | **密度优先** | 一屏要能装下条目名、属性、关系、来源。正文 14px、行高 1.65、信息表行高 1.4。不做大 hero、不做通栏留白 |
| 2 | **结构恒定** | 每个词条页同一套骨架（面包屑 → 标题栏 → 分块 tab → 正文 + 信息表 → 数据来源），读者第二次来就知道东西在哪。**页面之间只换内容，不换版式** |
| 3 | **表格与信息表是一等公民** | 不是 Markdown 的附属品：信息表有固定字段顺序与分组，长表格有 sticky 表头，矩阵用表格表达 |
| 4 | **单一强调色 + 大量中性灰** | 强调色只用于链接、主按钮、当前选中项；其余靠灰阶层级。不用彩色区块铺底 |
| 5 | **状态必须可读且不只靠颜色** | 已核实 / 草稿 / 墓碑 / 未认领 / 链接待核——每态同时有**图标或文字**，色盲用户也能分辨 |
| 6 | **不做装饰** | 无渐变、无大面积彩色底、无阴影堆叠；用 1px 边框 + 极轻阴影表达层级。**「无数据」永远显示为「无数据」而不是空或 0** |
| 7 | **可访问性与暗色是一等需求** | 对比度达 WCAG AA、键盘可达、`prefers-color-scheme` 自适应 + 手动切换、`tabular-nums` 让版本号与哈希对齐 |

## 2. 颜色令牌

两色制：**品牌色**（导航、主按钮、选中态）与**链接色**（大量内链）。区分二者是因为 wiki 的内链密度极高，链接需要最符合预期的颜色，而品牌色负责「这是哪个站」。

| 令牌 | 亮色 | 暗色 | 用途 |
| --- | --- | --- | --- |
| `--brand` | `#12796f` | `#3fd0bd` | 顶栏、主按钮、当前分区、选中 tab 的下划线 |
| `--brand-weak` | `#e6f4f2` | `#12302c` | 品牌色的淡底（选中的筛选项） |
| `--link` | `#1a56db` | `#8ab4ff` | 所有站内链接、外链（外链额外带 ↗ 图标） |
| `--link-visited` | `#6d28d9` | `#c4b5fd` | 已访问的站内链接 |
| `--bg` | `#ffffff` | `#14171a` | 页面底 |
| `--bg-subtle` | `#f6f7f9` | `#1b1f23` | 信息表、代码块、斑马行的底 |
| `--bg-inset` | `#eef0f4` | `#22272c` | 输入框、标签底 |
| `--border` | `#e3e6ea` | `#2c3238` | 分隔线、卡片边框 |
| `--border-strong` | `#cfd4db` | `#3a4249` | 表格表头下边线、输入框聚焦前 |
| `--text` | `#1b1f24` | `#e6e9ee` | 正文 |
| `--text-muted` | `#5a6472` | `#a3adba` | 次要文字、字段名 |
| `--text-faint` | `#8b95a3` | `#78828f` | 时间戳、快照日期、脚注 |

**语义色**（状态与风险，必须与图标或文字同时出现）：

| 令牌 | 亮色 | 暗色 | 用于 |
| --- | --- | --- | --- |
| `--ok` | `#1a7f37` | `#4ade80` | 已核实、实测兼容、链接可达 |
| `--warn` | `#9a6700` | `#fbbf24` | 草稿、未核实、链接待核、快照过期 |
| `--danger` | `#b42318` | `#f87171` | 已知不兼容、冲突、墓碑、构建脚本风险 |
| `--unknown` | `#6b7280` | `#9ca3af` | **未声明 / 无数据**（独立于 warn：这是「不知道」，不是「有问题」） |

> `--unknown` 单独成色，是本项目数据纪律的视觉化：`未声明 ≠ 不兼容`、`无数据 ≠ 0`。

## 3. 字体与排版

```css
--font-sans: system-ui, -apple-system, "Segoe UI", "Microsoft YaHei",
             "PingFang SC", "Noto Sans CJK SC", sans-serif;
--font-mono: ui-monospace, "Cascadia Code", Consolas, "JetBrains Mono", monospace;
```

- **不引入网络字体**（市场用了 Google Fonts 的 Archivo）。理由：中文站点引入西文字体收益极小、首屏成本明显，且 `system-ui` 在各平台的中文渲染最好。
- 字号阶梯：`12`（脚注/快照）/ `13`（信息表字段名、标签）/ `14`（正文、卡片）/ `16`（小节标题）/ `20`（词条标题）/ `24`（首页标题）。
- 字重：正文 400、字段名 500、标题 600、数字强调 600。
- **`font-variant-numeric: tabular-nums`** 用在：信息表、版本矩阵、下载量、`sha256`、日期。等宽内容一律 `--font-mono`。
- 中文排版规则：中英文之间一个空格、标点用全角、代码与包名不换行断字（`word-break: keep-all` + 溢出滚动）。

## 4. 布局

| 断点 | 词条页 | 分区页 |
| --- | --- | --- |
| ≥ 1280px | **两栏**：正文（自适应，最大 72ch）/ 信息栏（完整度 + 相关 + 信息表 + 目录，280px，吸顶）。**「相关」不再单独占左边一列**——240px 只放一小块跳转列表，把正文挤窄了（评审：「不要放在左边，太占空间」） | 顶部筛选条 + 卡片两列 |
| 768–1279px | 两栏：正文 + 信息表（信息表移到正文**上方**，读者先看「这是什么」） | 卡片两列 |
| < 768px | 单栏；目录折叠成「本页目录」折叠块；信息表在标题下方 | 卡片单列，筛选条横向滚动 |

顶栏常驻：品牌 + 十二个分区（可横向滚动）+ 搜索框。**搜索框永远在顶栏**，不做「点图标才展开」——这是高频入口。

## 5. 组件规范

### 5.1 词条页骨架（所有 kind 共用）

```
面包屑：首页 › 插件 › 兼容层 › dsh-loader
┌──────────────────────────────────────────────────────────┐
│ dsh-loader  [已核实] [含 Web UI]            [编辑] [纠错] │  ← 标题栏
│ 别名：DSH 加载器 · 兼容层 · 2 篇教程引用过它              │
├──────────────────────────────────────────────────────────┤
│ 正文 │ 关系 │ 兼容 │ 出现在哪些包 │ 数据来源               │  ← 分块 tab（下划线指示）
├──────────────────────────────────────────────────────────┤
│ 正文（含 TOC）                          │ 信息表（分组）   │
└──────────────────────────────────────────────────────────┘
```

- **tab 用下划线指示，不用药丸按钮**（药丸是宣传页语言）；tab 上带计数，与 MC百科一致（`Mod资料 (1045)`）。
- **信息表**用 `<dl>`：字段名 13px `--text-muted`、值 14px `--text`；按「基本信息 / 兼容 / 来源」分组，组间一条 1px 分隔。
- **数据来源 tab**：列出每个采集字段的来源与快照时间；页脚另有一行简要版。

### 5.2 徽章体系（四种，形状统一为 12px 圆角小矩形）

| 类型 | 例子 | 颜色 |
| --- | --- | --- |
| 状态 | 已核实 / 草稿 / 墓碑 | `--ok` / `--warn` / `--danger` |
| 来源 | awesome / 市场 / 人工 / 引用自 npm | `--bg-inset` + `--text-muted` |
| 风险 | 桌面操控 / 网络访问 / 凭据 / 构建脚本 | `--danger` 描边（不用实底，避免页面变红） |
| 口径 | 实测 / 未核实 / 未声明 | `--ok` / `--warn` / `--unknown` |

### 5.3 表格、矩阵、卡片

- **表格**：无斑马纹，1px 行分隔；表头 sticky；首列可 sticky；单元格内代码用 `--font-mono` 13px。
- **版本矩阵**：就是表格，四态符号 `✔ 实测` / `✘ 不兼容` / `? 未核实` / `– 不适用`——**符号 + 文字**，不靠色块。
- **卡片（分区页）**：紧凑两行——第一行名称 + 来源徽章 + 外链图标；第二行一句话 + 标签行；右上角是「词条 →」或红链「写这一条」。**不用封面图**（外部源没有统一封面，强行配图会变成拼贴）。
- **红链**：`--text-faint` + 虚线下划线，hover 提示「尚未收录 · 写这一条」。
- **命令块**：`--bg-subtle` 底 + 等宽 + 右上角复制按钮；安装类命令默认展示 `dsh plugin …` 原文，不做「一键安装」按钮（没有后端，避免假承诺）。

### 5.4 「装在哪」落点图

用一张**纯 HTML/CSS 的分层图**（不是图片，便于随规范变化更新与暗色适配）：

```
$DSH_HOME (~/.dsh)
├─ profiles/<name>/         ← 插件与层栈（dsh plugin add 落点）
├─ skills/                  ← 技能包
├─ .agent-presets/          ← 预设与人设
├─ AGENTS.md                ← 全局指令
└─ cordis.patch.yml         ← 机器级 patch 层

项目根/.dsh/skills          ← 项目级技能（跟随 cwd）
```

放在首页与各分区页顶部，并在相关词条里复用同一组件的精简版。

## 6. 与市场视觉的对照（为什么必须换）

| 维度 | 市场（纸墨朱砂） | 百科（本方案） |
| --- | --- | --- |
| 取向 | 宣传页：说服你去看 | 工具：让你查完就走 |
| 首屏 | hero + 插画 + 统计大字 | 搜索 + 分区 + 最近更新 |
| 强调色 | 朱砂红（暖） | 青绿（品牌）+ 靛蓝（链接） |
| 字体 | Google Fonts 的 Archivo | `system-ui` 系统字体栈 |
| 层级表达 | 卡片 + 阴影 | 1px 边框 + 灰阶 |
| 动效 | SVG 轨道动画 | 只有 hover/focus 的即时反馈 |
| 信息密度 | 低（一屏一包） | 高（一屏一条目 + 属性 + 来源） |

**顺带解决一个法律问题**：市场的视觉「设计灵感源自 `awesome-dsh-plugin.com`」并在页脚署名了许可（且该署名与上游自述 MIT 存在口径冲突，见 [04](04-mcmod-reference.md) §7.3）。百科不再复用那套视觉，因此**不产生该署名义务**，页脚只保留对这一生态的自愿鸣谢与外链。市场页脚的口径问题仍应回报修正。

### 8.1 站点标识（logo / favicon）

**形态**：16×16 像素画 —— **品牌墨绿瓷砖 + 白色文档 + 两条深色文字线 + 一条琥珀高亮行**。
选它的三个理由：与站点的像素美学（`PX=4`、`crispEdges`）同源；16px 下仍读得出「一条词条」；
**故意不含任何像 DeepSeek 官方标识的元素**——本站是非官方社区资料站，标识只表达
「这是一本中文百科」，不暗示官方身份（§8.4）。

**生成**：`node scripts/logo.mjs`（**零依赖**，脚本里自带 PNG 与 ICO 编码器）。
网格定义在脚本顶部的 `MARK` 常量里，改标识只改那一处；产物**入库**，CI 不跑它。

| 产物 | 用途 |
| --- | --- |
| `favicon.ico` | 16/32/48 三档（ICO 内嵌 PNG），`rel="icon"` 的老浏览器兜底 |
| `favicon-16/32/48.png` | 显式尺寸声明用；也方便外部服务（如搜索引擎）取图 |
| `favicon.svg` / `logo.svg` | 矢量版（像素网格逐格导出），现代浏览器优先取它 |
| `apple-touch-icon.png` | 180×180，iOS 添加到主屏 |
| `og-image.png` | 1200×630 社交卡：品牌底 + 放大标识（**不排汉字**，避免依赖字体） |

**两处接线**（改标识时都要看）：

- 页面 `<head>`：favicon 用**相对路径**（本地预览、根域、子路径部署都不裂）；
  `og:image` 必须是**绝对 URL**（爬虫不解析相对路径）→ `https://dshbaike.com/og-image.png`；
- rail 里的品牌行：`web/pedia.js` 的 `BRAND_MARK_SVG`（手写成 6 个 `<rect>`，
  几何取自同一套网格）——比内联整张 16×16 网格小两个数量级。
| 仓库名 | `dshbaike`（与域名一致） |
| 品牌大小写 | 全小写 **`dshbaike`**（域名风格）；不用 `DSHBaike` / `DshBaike` 这类驼峰 |

### 8.1 域名与仓库名可以一致，也可以不一致

当前三者同名（站名「DSH 百科」/ 域名 `dshbaike.com` / 仓库 `DSH-PackForge/dshbaike`），省得记两套。

但这条不是硬约束：域名是**入口**，仓库名是**工程标识**，参照物就把两者分开了——MC百科的域名是 `mcmod.cn`，既不含「百科」也不含 Minecraft 全名。**换域名不需要改仓库、不需要改站内链接结构**——词条的主键是自增编号（[02](02-data-contract.md) §2），与域名无关。所以域名采购可以推迟到 M4 上线前，先用免费子域（§8.2）。

### 8.2 托管路线

**仓库已转为公开**（2026-10-02），所以托管回到最省事的一条：**GitHub Pages**，零外部账号、零 secrets，`.github/workflows/pages.yml` 在每次 `main` 通过校验后构建并发布。

| 方案 | 成本 | 地址 | 状态 |
| --- | --- | --- | --- |
| **GitHub Pages**（现行） | 免费 | `https://dshbaike.com`（自定义域；原 `dsh-packforge.github.io/dshbaike/` 会 301 过来） | ✅ 已接入 |
| Cloudflare Pages | 免费额度足够 | `dshbaike.pages.dev` | 备选：要挂 `dshbaike.com` 根域时更省事 |
| Vercel / Netlify | 免费额度足够 | `dshbaike.vercel.app` / `.netlify.app` | 备选 |

**子路径部署是硬约束，不是小事**：GitHub Pages 的项目站挂在 `/<repo>/` 下，所以构建期必须写对部署根——`node scripts/build.mjs --base=/dshbaike/`。它会同时改写两处：生成页的 `<base href>`（嵌套页靠它解析相对资源）与 boot 里的 `base`（前端据此取 `data/*.json`）。模板里写死的那行 `<base href="/">` 会被构建期替换掉，不要手改模板去迎合某个部署形态。挂上自定义域（根路径）时，去掉 `--base` 即可。

站内所有链接都是相对的（`pedia.css`、`data/search.json`）或由 boot 的 base 拼出来的，所以同一份代码在根域与子路径下都能跑，切托管方不需要改数据。

**子路径部署的自检清单**（这三条都出过问题，改完部署相关代码请逐条过）：

1. 生成页的 `<base href>` 等于部署根（由 `--base` 在构建期写入，模板里那行是占位）。
2. boot 里的 `base` 与上一条一致（`window.__PEDIA__.base` / `__PEDIA_BASE__`）。
3. **首页手写外壳里的 `base: "./"` 必须保持相对**——前端 `normalizeBase()` 曾把 `./` 塌成 `/`，本地根路径下一切正常，一挂到 `/dshbaike/` 就变成请求 `/data/search.json` 而 404。

本地复现子路径（不要只在根路径下自测）：

```bash
node scripts/build.mjs --base=/dshbaike/
node scripts/dev-server.mjs 8812 --prefix=/dshbaike/   # → http://127.0.0.1:8812/dshbaike/
```



### 8.3 非官方声明（一句话，只在页脚出现一次）

> 非官方社区资料站。

就这一句，放在**整站页脚**，小字、`--text-faint`。**不要往顶栏、词条信息表、卡片或每页页脚里再抄一遍。**

为什么这么克制：这句话说一次是事实，说四次就成了噪音，而且会把真正有用的信息淹掉——读者需要的是**这一条具体有什么风险**（「⚠ 桌面操控」「⚠ 会写 build 脚本」，由词条的 `risk` 字段驱动，见 [06](06-zones-and-entries.md) §4），不是每页都被告知「自行评估风险」。后者既没提供信息，也在暗示我们对自己收录的东西没底。

「关于」页可以写完整的来龙去脉（社区维护、与 DeepSeek 官方无隶属关系、内容许可是什么），但那是**一个页面**，不是散落在全站的字条。

### 8.4 不得使用的标识与措辞

- 不用 DeepSeek 的 logo / 吉祥物 / 官方配色作为自己的品牌标识；
- 不写「官方」「唯一」「认证」「推荐」这类词；
- 引用官方仓库、规范、外部源时**只做描述性引用**（名称 + 链接），不把它做成自己的品牌资产；
- 分区页里的外部源（awesome / dshbase / 市场）署名只写来源与链接，**不替对方声明许可证**（[04](04-mcmod-reference.md) §7.3）。

### 8.5 顶栏、首页与页脚的品牌区写法

```
┌───────────────────────────────────────────────────────────┐
│ DSH 百科        [界面与客户端][插件][整合包][启动器]…  ⌕   │  ← 顶栏：站名 + 分区 + 搜索
└───────────────────────────────────────────────────────────┘

首页 hero：
   DSH 百科
   一站式的 DeepSeek Harness 中文百科                        ← 主标语（20px 级，正文之上）
   [ 搜索 词条 / 插件 / 教程 … ]                             ← 输入框紧随其后

页脚：
   DSH 百科 · dshbaike.com · 数据快照 2026-10-01 · 代码 CC0 / 正文 CC BY-SA
   非官方社区资料站
   生态：awesome-dsh-plugin.com ↗ · dshbase.com ↗ · 整合包市场 ↗ · 规范仓库 ↗
```

三条规矩：

1. **标语放首页与 OG，不放顶栏；顶栏只留站名 + 分区 + 搜索**。合规声明只在页脚一次（§8.3），不要为了「保险」把它塞进顶栏或每页。
2. **域名只在页脚出现**——顶栏空间要留给十二个分区与搜索框（见 §4 布局）。
3. **`title` 用半角 `|`，正文用 `·`**；`DSH 百科` 与 `DeepSeek Harness` 按官方大小写（中英文之间加空格，见 §3）。

### 8.6 标语反过来约束设计

主标语承诺「**一站式**」，而这句话是**可以被读者当场验证**的，所以它带来一条硬要求：

> **任何一个分区页都不允许是空的。** 每个分区至少给出一个可用入口——本站词条、或一个明确的外部源（`external-index` 的「去源头看全量」也算）。空分区页会把「一站式」变成笑话。

配套的两条：十二个分区必须**全部可达**（顶栏可横向滚动，不允许藏在二级菜单里）；分区页的「来源区块」必须显示各源快照时间与状态（[07](07-multi-source-zones.md) §5）——「一站式」不等于「我们自己什么都有」，而等于「**从这一页出发你能到达任何东西**」。

## 9. 跟随光标的吉祥物（大肥鱼）

### 9.1 光标本身不动（一次试过又退回来的决定）

第一版做的是**替换系统指针**（自绘箭头 + 鲸鱼娘头像 + 备用像素手），做完之后否掉了：

> **指针是高频操作的手感基线，不是装饰位。** 选中一段文字、拖滚动条、拖拽选中、右键菜单——这些每天都在做，肌肉记忆建立在系统指针上。换成自绘像素画，可读性、热点落点、高 DPI 缩放、Safari 不认 SVG 指针这一串问题全要跟着处理，收益只是「好看」。**得不偿失。**

所以 `cursor` 一律回到系统默认。**吉祥物改成跟在光标后面的宠物**：它有形象，但不占用指针这个交互件。

### 9.2 素材是第三方的，署名是硬要求

自己画的像素版（32×32 的「鲸鱼娘头像 + 侧向鲸尾」）试过，形象能站住但**画工不够**——与其硬画，不如用社区里现成做得好的。现在用的是 [`YunYueSama/codex-deepseek-pet`](https://github.com/YunYueSama/codex-deepseek-pet) 的宠物精灵（「大肥鱼」，一只圆滚滚的鲸鱼娘）。

| 项 | 内容 |
| --- | --- |
| 许可 | **大肥鱼项目署名许可 1.0**：允许使用、修改、分享及**商用**，条件是署名 + 保留许可 + 说明修改 |
| 与本站纪律的关系 | **不冲突**：它不是 NC 许可，不污染下游（见 [LICENSE](../LICENSE) 里「为什么不用带 NC 的许可」） |
| 我们所做的修改 | 取出待机 6 帧与行走 8 帧，按统一外框裁切、等比缩放到 192×192 画布、量化到 160 色 PNG |
| 署名位置 | 每页页脚 + [`web/mascot-CREDITS.txt`](../web/mascot-CREDITS.txt) + 许可全文 [`docs/third-party/`](third-party/fatfish-attribution-license-1.0.txt) |
| 第三方边界 | 许可只覆盖作者有权授权的部分；**角色形象（鲸鱼娘 / 大肥鱼）本身是社区二创**，权利属相应权利人。本站的署名不代表原作者或 DeepSeek 官方认可本站 |

页脚那一行是许可意义上的「使用者容易找到的位置」，**不是可选装饰**——所以它由 `pedia.js` 的 `SITE.mascotAuthor / mascotRepo / mascotLicense` 驱动，改素材必须同步改它。

### 9.3 怎么跟

| 项 | 取值 | 为什么 |
| --- | --- | --- |
| 跟随方式 | 插值 0.18/帧 + rAF | 追得比光标慢半拍才有「跟」的感觉；等速贴上去像贴纸 |
| 落点 | 光标右下 `+34, +44`，锚点取**底边中点** | 落在指针斜后方，且换帧、换套、左右镜像时人物都不跳 |
| 朝向 | 水平位移超过 6px 死区才镜像 | 小幅抖动就翻面会闪 |
| 在走还是站着 | 只看**指针**：140ms 窗口内累计位移 ≥3px 起走，且走起来至少持续 320ms | 站着眨眼、走起来迈步，是这只宠物本来的两套动作。**不能拿「我离目标还剩多远」当速度**——追上了算停、一动又算走，会在阈值附近来回切，两套精灵互相闪（第一版就是这么写的，见 §9.6） |
| 指针离开窗口 | 淡出（`opacity` 200ms） | 不然它会孤零零挂在页边 |
| 层级 | `z-index: 20` | 内容之上、左侧导航（30/40）之下：**不许盖住导航** |
| 事件 | `pointer-events: none` | 第一要务。绝不挡点击、选字、滚动 |
| 不挂的场景 | `(hover: none)` 触摸设备、`prefers-reduced-motion: reduce` | 前者没有光标，跟随只会变成一块乱飘的图；后者是不该动的东西别动 |

分两半，各管一件事，不互相覆盖 `transform`：**位置、镜像、前倾**由 JS 算（`pedia.js` 的 `mountMascot()`），**换帧**由 CSS 做（`background-position` + `steps()`）。

### 9.4 两套横排精灵与体积

- `web/mascot-fatfish-idle.png`：6 帧（第 5 帧是眨眼），`steps(6)`、2.4s 一轮；
- `web/mascot-fatfish-walk.png`：8 帧行走循环（朝左），`steps(8)`、640ms 一轮；向右靠 CSS `scaleX(-1)` 镜像，省掉一套右向帧；
- 每帧 192×192 正方形画布，页面按 96×96 显示（2× 供高 DPI），所以换帧位移正好是 `帧宽 × 帧数`（-576px / -768px）。

**体积**：32 位 PNG 下行走 8 帧要 333KB，量化到 160 色后是 63.9KB、待机 17.7KB（128 色时头发渐变的色带已经看得见，160 色只多 2KB）。另外行走那张只在**第一次走动**时才加载（`.mascot--walk` 规则触达后浏览器才取图），所以首屏只付待机的 17.7KB。

### 9.5 重新生成素材

```bash
python scripts/prepare-mascot.py [源精灵图路径]
```

一次性脚本，**不在构建链里、CI 不跑它**（需要 Pillow，而本仓库的构建是零依赖的）。换素材或换帧数时手动跑一次，产物入库；路径、许可与「已作修改」的说明同步写进 `web/mascot-CREDITS.txt`。

### 9.6 这个部件的坏法都写成了测试

`scripts/test-mascot.mjs` 除了接线与署名，最后一段会**用假 DOM 把 `mountMascot()` 真的跑起来**：喂合成的鼠标事件与帧时钟，只观察它切换 `.mascot--walk` 的次数。四类场景各一条断言——连续移动只切一次、停住回待机只切一次、移动中的短暂停顿不闪回、微小抖动不来回切。

之所以专门这么做：浏览器里跑不了（沙箱禁命名管道，Chromium 起不来），而**「静止→移动时两套精灵来回闪」正是第一版的真实故障**——当时的判定用了「我离目标还剩多远」当速度。这类状态机 bug 靠读代码很难发现，靠断言才守得住。

### 9.7 还没做的

- **开关**：现在强制跟随，没有任何 UI 能关掉（只能靠系统级「减少动态效果」）。侧栏已有主题色切换，加一个「关掉吉祥物」的按钮是十几行的事；
- **久不动的行为**：现在指针停住她就原地眨眼。要不要「长时间不动就走到角落坐下/睡着」（素材里有睡觉帧）还没定；
- **其他位置复用**：词条页空状态、404、宣传页要不要也放她，尚未决定（宣传页不加载 `pedia.js`，所以现在没有）。
