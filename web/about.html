关于本站与维护者

DSH百科是一站式的 DeepSeek Harness 中文百科：把「怎么装、怎么配、各家长什么样」整理成 能查、能核对、能照着做的页面。

谁在维护

站点由 DSH-PackForge 维护：仓库在 DSH-PackForge/dshbaike， 域名 dshbaike.com。本站没有后端：页面是构建期生成的静态 HTML， 每次改动都走 GitHub 上的提交与评审。

词条级维护者是另一回事，也是本站维护方式的重点：每条词条都可以由人 认领维护（词条页上的「我来维护」），认领之后，改这一条的请求会先请他们过目。 所以本站没有一份统一的「编辑名单」——你打开任意一条词条，页面自己会告诉你 这一条是谁在跟进。

按什么规矩写

这些不是口号，是站点实际执行的规则（可以在任意页面上核对）：

  • 只写能指到出处的：每条外部事实都带来源与快照日期（如「69 star，快照 2026-10-02」）。 查不到出处就写「未核实」，不猜、不补全。
  • 不替读者做决定：本站标「具备什么能力」（如某启动器的平台、版本格式、 是否支持 .dspack），不写「哪个更好」。缺点只写事实与代价，不做负面定性。
  • 刻意不全量收录：插件生态有数千个条目，全量目录交给 awesome-dsh-plugin.com 与 dshbase.com——它们做得比我们好。 本站收的是被教程引用过、或被整合包用到的那些，为它写一篇能解释机制与坑的聚合页。
  • 倾向可核查的形式：结论尽量给可复现的做法（命令、字段、文件路径）， 而不是「据说」「一般情况下」。

怎么参与

  • 发现一个小错：词条页上有「改一句话」「改字段」「纠错」等表单， 填完由自动化提交改动、再由人过一遍——不需要你装任何东西、也不需要懂 Git。
  • 认领一条词条：词条页上的「我来维护」；认领后你会成为它的维护者。
  • 写一条新词条：红链（「写这一条」）或 新增词条 表单； 编号与骨架由自动化处理，你负责内容与出处。
  • 站点本身的问题（导航、搜索、样式、渲染、想加分区或词条类型）： 走这张表——这类要人来判断与设计。

与其它站点的关系

  • awesome-dsh-plugin.com：社区精选目录，负责「发现」；
  • dshbase.com：中文入门与排错；
  • dsh-pack-market：整合包索引与启动器认领（数据上游）；
  • DSH-PackForge 规范仓库：manifest、pack-structure、index 等契约的定义者；
  • dsh-plugin-mesh：按功能铺开的全量生态图（自动采集，未经本站核实）；
  • dsh-myskin：本站配色参考的海洋风格皮肤框架。
