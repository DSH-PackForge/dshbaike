# DSH 百科

**一站式的 DeepSeek Harness 中文百科** · 域名 `dshbaike.com` · 仓库 `DSH-PackForge/dshbaike`

> **状态：设计阶段（设计稿待评审，尚无代码）。** 本轮只交付设计文档，评审通过后再进入实现。
>
> 站名 **DSH 百科**，主标语 **「一站式的 DeepSeek Harness 中文百科」**；先上免费子域，域名可在 M4 前再买。品牌与命名规范见 [08](docs/08-visual-system.md) §8。
>
> 仿 MC百科（[mcmod.cn](https://www.mcmod.cn/)）的信息架构，为 DSH（DeepSeek Harness）生态做一部**词条化**的百科。主站是两个功能的合体：
>
> 1. **分区层（资源整合）**：十二个一级分区，**导航顺序按「你每天要用的」排**——界面与客户端 → 插件 → 技能包 → 启动器 → 整合包 → MCP 与工具接入 → 主题与皮肤 → 素材与本地化 → 预设与人设 → 指令与配方 → 工具链 → **规范与协议垫底**（查阅用，不是入口）。顺序的唯一来源是 `data/registry.yml` 的 `zoneOrder`（校验规则 26 强制它与分区文件完全对应）；前五个是定死的顺序，**新增分区落在第六个起的「其余」段里**。**装配位置分层**（交互/启动/扩展/配置/外观/分发/元）是另一套推导规则，用来找「下一个分区该不该立」，见 [06 §2](docs/06-zones-and-entries.md)。卡片 + 一句介绍 + **外链到外部源**，不编号、不写正文。
> 2. **词条层（解释与教程）**：用户贡献的编号词条 `/<kind>/<n>.html`（参考 MC百科的 `/class/<n>.html`），写机制、关系、兼容性与教程。
>
> 两层之间靠**红链**连接：分区里还没有词条的条目显示「写这一条」，点进去就是领号命令与模板。详见 [06 · 分区层与词条层](docs/06-zones-and-entries.md)。

## 这是什么 / 不是什么

| | 说明 |
| --- | --- |
| **是** | 一个**两层**的站点：**分区层**（十二个一级分区，按装配位置分层；卡片 + 外链，负责「去哪拿」）+ **词条层**（编号词条，负责「看懂它」） |
| **是** | 一个静态百科站点：每个实体一页（**MC百科式自增数字编号**，如 `/plugin/12.html`），能搜索、能按分类浏览、能顺着关系往下翻 |
| **是** | 一个**人工词条为主 + 外部源聚合为辅**的 wiki：词条改动走 PR，git 历史即编辑历史 |
| **是** | **资源整合层**：插件事实（star / 下载量 / 收录日期 / 安装命令）引用 `awesome-dsh-plugin.com` 等外部源并外链，不落元数据副本 |
| **是** | 市场（`dsh-pack-market`）的**下游消费者**：整合包数据直接读市场索引与 manifest，不重复采集 |
| **不是** | 第二个市场：不负责下载与安装分发，安装命令指回市场与 `dspack install` |
| **不是** | 第二个插件目录：**不做插件全量收录**（awesome 4400 条、dshbase 7800+ 条在做）；插件词条只收「官方来源 / 被教程引用 / 被整合包使用 / 有人认领」的，十几到几十条量级 |
| **不是** | 入门教程站：`dshbase.com` 已占住「DSH 是什么、怎么装」；本百科侧重**机制解释、关系、兼容性、包内容构成**，并给外部教程做索引卡 |
| **不是** | 有后端的社区站：没有账号、积分、评论、评分、在线编辑器——这些需要服务端与运营，首版一律不做 |

## 待确认项

来自各设计文档的问题汇总，评审时逐条给结论：

1. **插件收录门槛的松紧**（门槛本身已定：官方来源 / 被教程引用 / 被整合包使用 / 有人认领）。待定的是**是否再加配额**（例如首版插件词条不超过 30 条）；以及官方包 `@deepseek-ai/*` 走插件词条还是概念词条。
2. **热度数字的引用方式**：awesome 的下载量与 star 是「建条时抓一次 + 页面标快照日期」，还是每次构建刷新（会破坏离线可构建）？倾向前者。
3. **市场页脚的许可证口径不一致**（处理方式已定）：市场页脚称 awesome 站为 CC0 1.0，该站自述 MIT（[04](docs/04-mcmod-reference.md) §7.3）。百科侧已定：署名**只写自愿鸣谢 + 外链、不写协议名**；仍建议回报 `dsh-pack-market` 修正页脚。词条正文许可已定为 **CC BY-SA 4.0**（其余 CC0，见 [LICENSE](LICENSE)）。
4. **周期性空提交**：`collected/` 定时刷新会产生「只有快照时间变化」的提交，是否接受（[03](docs/03-directory-and-pipeline.md) §8）。
5. **词条正文的语言策略**：首版只做「字段级可选英文」，不做双语正文——是否需要英文站点。
6. **SKILL.md 的 `invocation` 字段**：仓库里真实技能在用，实现侧的字段白名单里却没有（[02](docs/02-data-contract.md) §3.2 标为冲突），需实机验证一次。
7. **资料（`resource`）二级词条是否在 M3 启动**：取决于「从 `cordis.patch.yml` / `dsh.client.inject` 半自动提取资料候选」这条通道能否走通。
8. **分区划分与命名**（[06](docs/06-zones-and-entries.md) §2）：分区改为按**装配位置七层**划分（交互/启动/扩展/配置/外观/分发/元），共十二个；新增的「**界面与客户端**」（官方 Web UI / 桌面端 / TUI / CLI / headless）命名是否合适？备选：`/clients`「客户端」、`/forms`「运行形态」——只需改一个目录名与标签，不影响其它设计。
9. **官方形态与第三方是否分区展示**：界面与客户端分区里 `official` / `third-party` / `launcher` 用徽章区分（[06](docs/06-zones-and-entries.md) §2.3）。是否同意「第三方桌面壳默认展开风险提示」（它会拿到本机权限）？
10. **二级标签是否直接复用 awesome 的 24 个分类键**（[06](docs/06-zones-and-entries.md) §3），避免造第三套体系。
11. **未认领的个人启动器是否收录**（[07](docs/07-multi-source-zones.md) §6）：倾向收录并显式标「未在注册表认领」+ 认领引导；但要确认不会变成「收录 ≠ 背书」的口径问题。
12. **源的收录门槛**（[07](docs/07-multi-source-zones.md) §3）：任何外部源只要提供可抓的 JSON 就能进「本分区的来源」区块，还是需要人工评审（避免接入野源、死源）。倾向后者 + `reliability` 分级。
13. **视觉配色**（[08](docs/08-visual-system.md) §2）：方案取「青绿品牌 + 靛蓝链接」（wiki 内链密度高，链接色最符合读者预期）。若你有偏好的主色（例如更接近 MC百科的观感），换掉两个令牌即可，不影响其它设计。
14. **完整度指标是否采纳**（[09](docs/09-mcmod-entry-deepdive.md) §3.1）：分母按 kind 定义（插件：定位/正文/关系/兼容/外部源指针/出现在哪些包），页面显示百分比 + 可点击的缺项清单。它把「这条写全了没有」变成公开数字，但也可能诱导为凑数而填字段——需要定「推荐级字段是否计入」。
15. **许可证是否独立成块**（对应 MC百科的 `Mod协议` 分块，[09](docs/09-mcmod-entry-deepdive.md) §1 第 16 项）：方案是插件/整合包词条都有 `licenseRefs`（可多条，如本体 MIT + 内置资源 CC BY）。要不要再进一步，把常见许可证本身做成概念词条（解释 MIT 与 CC 系的区别）？

## 许可证（已定，完整说明见 [LICENSE](LICENSE)）

分许可，按路径区分：

- **词条正文**（`data/<kind>/*.md`）：**CC BY-SA 4.0**（署名 + 相同方式共享）——正文是本站唯一的原创资产，需要防「被静默搬走再商业化」
- **其余全部 CC0 1.0**：代码与脚本、结构化数据（`registry` / `taxonomy` / `sources` / `entities` / `zones`）、采集与构建产物（`collected/**`、`web/data/**`）、设计文档（`docs/**`）——**下游（市场 / 启动器 / 第三方工具）零法律摩擦**
- 外部源与上游仓库的元数据：**只引用（带快照日期）与外链**，不落副本；外部教程只做索引卡，不转载正文
- 不使用带 NC 的许可（MC百科用的是 BY-NC-SA）：NC 会让商业化客户端无法合法消费本站数据，站点会变成数据孤岛

⚠️ 另需处理一处既有的许可证不一致：`dsh-pack-market` 页脚称 `awesome-dsh-plugin.com` 为 CC0 1.0，而该站自述 MIT（[04](docs/04-mcmod-reference.md) §7.3）。百科的署名**不写协议名**，并把这条回报给市场修正。

## 本地预览

```bash
node scripts/validate.mjs   # 校验词条、分区与编号契约（0 errors 才能提 PR）
node scripts/build.mjs      # 离线构建：写 web/data/**、web/<kind>/<n>.html、web/<zone>.html
npx serve web               # 任意静态服务器；也可直接开 web/index.html 看演示数据
```

构建**完全离线**（只读 `data/**` 与 `collected/**`），零第三方依赖，同一输入两次构建产出逐字节一致。
